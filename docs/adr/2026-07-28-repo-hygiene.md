# Repo hygiene: generated output is built, photos are stripped, the S3 hybrid build is a dead end

- **Status:** Accepted
- **Area:** ota-release
- **First decided:** 2026-07-28 · **Last changed:** 2026-09-09
- **Boards:** all

## Context

Three unrelated findings that each became a standing rule for a public
repository: a committed build artifact that drifted from its source, photos
that carried a contributor's location into public history, and an attempt to
tune the S3's memory through the SDK configuration that could not be made to
build.

## Decision

**Generated artifacts are never committed.** The embedded History web page
(`include/platform_esp32/webapp_dist.h`, a gzipped blob) used to be checked
in and regenerated by hand. Since 2026-07-28 it is git-ignored and a build
output: every device build and flash target depends on it, `make clean`
removes it, and the release workflow builds it before `pio run`. That made
node a dev dependency of device builds (not of `make sim`); bare `pio run`
needs `make webapp` first. The same rule covers the vendored esp-web-tools
bundle (2026-09-29). Accept the toolchain dependency, not the drift.

**Every photo is stripped of EXIF, GPS and XMP before it is committed.**
iPhone photos carry GPS and device data, and HDR shots append a gain-map
trailer JPEG, with its own metadata, after the main image's end-of-image
marker. The lossless strip walks the JPEG segments, drops APP1 and APP13,
keeps APP0 and APP2, and keeps bytes from the first SOS only through the
first `FF D9` AFTER it (searching from the file start finds an embedded
preview's end and truncates the image). It is done with a throwaway script
each time; nothing for it lives in `tools/`.

**`custom_sdkconfig` is not used on any env.** Setting it switches pioarduino
from the prebuilt Arduino libraries to the ESP-IDF hybrid compile, which does
not build for this project on either chip.

## Evidence

- Photo incident (per the working notes of 2026-08-09; the rewrite left
  nothing in the repository to cite): all seven wiring photos shipped with
  a contributor's home GPS coordinates in public history for about two weeks.
  Fixed by a `git filter-repo` blob rewrite of the whole history and a
  force-push of every branch and tag. Old commits may stay reachable on
  GitHub by SHA until purged. 3MF print files were checked the same day and
  carry only a printer-software designer id.
- S3 hybrid build (per the working notes; nothing was committed),
  2026-09-09, trying `CONFIG_SPIRAM_TRY_ALLOCATE_WIFI_LWIP=y`
  to move WiFi and lwIP buffers off the cramped internal heap: the option
  took effect in the generated `sdkconfig.json`, but the hybrid path (1)
  resolves `board_build.partitions` against the project root, (2) compiles
  every managed component from source with broken stock defaults (esp-modbus
  `static_assert`, then libsodium's undeclared `SODIUM_VERSION_STRING`, each
  fix revealing the next) and (3) ignores `build_src_filter`, so the sim,
  host and dltest sources would need a CMakeLists. Abandoned at step 2. No
  env sets `custom_sdkconfig` today (`platformio.ini`, checked 2026-11-04).

## Alternatives and dead ends

- A documented manual "regenerate the header" step: nothing fails when it
  is forgotten, and CI cannot catch what it never builds.
- Reading the `.gitignore` lines `sdkconfig.esp32-p4-micra-43` and
  `sdkconfig.defaults` as proof the P4 uses the hybrid path: they are
  fossils of the abandoned 2026-07 P4 revision-override attempt. A
  successful P4 build produces neither file. Hybrid is unproven on both
  chips; it fails differently on each.

## Consequences

- If the WiFi-buffers-in-PSRAM option is ever retried, install mode must
  stop WiFi before its flash write (a flash write disables the cache and
  makes PSRAM unreachable), and PSRAM bus contention with the RGB scanout
  must be weighed.
- Any commit that adds an image gets a metadata check; there is no exiftool
  on the build machine, a byte sniff for `Exif\0\0`, `<x:xmpmeta` and tag
  0x8825 does the job (ad hoc, like the strip; not scripted in the repo).
