# Stats tab: temperature history with a tap-to-zoom window, device info from the standard DIS, a manual clock

- **Status:** Accepted
- **Area:** ux
- **First decided:** 2026-06-29 · **Last changed:** 2026-09-08
- **Boards:** all; History needs an SD slot

## Context

The third bottom tab was a placeholder. The plan (2026-06-29) was Brew and
Boiler temperature graphs so heat-up and cool-down can be seen, an Info
view, and a time source. The working notes still describe this as "not
built yet"; git shows it was built the same day.

## Decision

- **Brew / Boiler / History / Info** behind a segmented selector, mirroring
  Settings.
- Brew and Boiler plot the boiler temperature against time from an
  in-memory ring sampled every 30 s while connected (`core::IHistory`;
  `platform::History::kSampleIntervalS`, capacity 24 h plus slack), with
  a set-point reference line, greyed no-data spans (before recording, and
  BLE gaps), and a +/- zoom over the time window. The title, value and zoom
  button that first sat above the chart were dropped: the selector names
  the section and the axis gives the values.
- Info reads the machine's standard Bluetooth Device Information Service
  (manufacturer, model, serial, firmware, software) once per connect, plus
  Uptime (2026-07-22) and an honest "NTP synced" state (2026-09-08).
- **Time is manual or NTP, never from the machine.** The local link exposes
  no clock, so the first clock was the internal RTC with a Set time page and
  a 12/24-hour toggle (2026-06-28); WiFi + NTP came later. Boards with a
  battery-backed RTC keep time across power-off.
- History (the shot log) was added with the SD card work and is covered by
  the shot-history records, not this one.

## Alternatives and dead ends

- Syncing the clock from the machine over BLE: not possible, no
  characteristic carries a date or time.
- A database for the temperature history: unnecessary, 24 h at 30 s is
  ~2,880 samples in RAM.
